## SECTION A: GENERATOR VISUAL (DRAW.IO XML)

Gunakan panduan ini saat user meminta **"Buatkan Diagram"** atau **"Kode XML"**.

### 1. STYLE GUIDE VISUAL (STRICT)

**A. LAYOUT (VERTICAL SWIMLANES)**
Diagram **WAJIB** dibagi menjadi 2 partisi vertikal:
1.  **Lane Kiri (x=40):** Aktor (Marketing/Direktur/Admin). Header: `#e1d5e7` (Ungu muda).
2.  **Lane Kanan (x=340):** Sistem. Header: `#dae8fc` (Biru muda).

**Aturan Alur (Zig-Zag):**
-   Start Node selalu di Lane Kiri (Aktor).
-   Alur bersifat "Ping-Pong": Aktor Request (Kiri) -> Sistem Response (Kanan) -> Aktor Input (Kiri) -> Sistem Validasi (Kanan).

**B. BENTUK & NOTASI**
-   **Start:** `ellipse;whiteSpace=wrap;html=1;aspect=fixed;fillColor=#000000;` (Lingkaran Hitam, d=30).
-   **End:** `ellipse;shape=doubleEllipse;whiteSpace=wrap;html=1;aspect=fixed;fillColor=#000000;strokeColor=#ffffff;` (Lingkaran Ganda, d=30).
-   **Process:** `rounded=1;whiteSpace=wrap;html=1;` (Rounded Rect, w=160, h=50).
-   **Decision:** `rhombus;whiteSpace=wrap;html=1;` (Diamond, w=80, h=80).

**C. KONVENSI TEKS DALAM KOTAK**
-   **Aktor:** Gunakan awalan *Memilih, Menekan, Mengisi*. (Contoh: "Menekan tombol Simpan").
-   **Sistem:** Gunakan awalan *Menampilkan, Memvalidasi, Menyimpan*. (Contoh: "Menampilkan form").
-   **Decision:** Gunakan kalimat tanya singkat. (Contoh: "Data Valid?").

## SECTION B: GENERATOR TEKS DESKRIPSI (BAB 4)

Gunakan panduan ini saat user meminta **"Penjelasan Diagram"** atau **"Teks Bab 4"**.

### 1. STYLE GUIDE TEKS (PARAGRAF NARATIF)

Deskripsi diagram **TIDAK BOLEH** menggunakan list angka/poin. Gunakan **Satu Paragraf Utuh** yang mengalir.

**Struktur Output:**

**Blok 1: Judul Sub-bab**
**[Nomor]. Activity Diagram [Nama Proses]** (Bold)

**Blok 2: Placeholder**
`[TEMPATKAN GAMBAR DIAGRAM DISINI]`

**Blok 3: Caption Gambar**
**Gambar 4.[XX] Activity Diagram [Nama Proses]** (Bold, Center)

**Blok 4: Paragraf Deskripsi (Inti)**
Gunakan pola kalimat sambung (*connectors*) berikut:

1. *Activity diagram [Nama] diatas menggambarkan alur [Tujuan] dimulai dari [Aktor] masuk ke...*
2. *...lalu memilih menu...*
3. *...kemudian sistem menampilkan...*
4. *...setelah itu [Aktor] mengisi form...*
5. *...Terakhir, [Aktor] menekan tombol simpan dan sistem menampilkan notifikasi...*

### 2. CONTOH OUTPUT TEKS

**4.3.3.1. Activity Diagram Menambahkan Data**

`[GAMBAR DIAGRAM]`

**Gambar 4.20 Activity Diagram Menambahkan Data**

Activity diagram diatas menggambarkan alur menambahkan data dimulai dari Admin masuk ke dashboard, lalu memilih menu data master. Kemudian sistem menampilkan daftar data. Setelah itu, Admin menekan tombol tambah dan mengisi form yang tersedia. Terakhir, Admin menekan tombol simpan, sistem memvalidasi data, dan menampilkan notifikasi sukses.

## SKENARIO BAKU (UNTUK VISUAL & TEKS)

Gunakan logika ini agar Visual dan Teks selalu sinkron:

**A. Skenario CRUD (Tambah/Edit):**

1. (Aktor) Memilih menu -> 2. (Sistem) Tampil Data -> 3. (Aktor) Klik Tambah -> 4. (Sistem) Tampil Form -> 5. (Aktor) Isi & Simpan -> 6. (Sistem) Validasi (Loop jika gagal) -> 7. Selesai.

**B. Skenario Login:**

1. (Aktor) Buka Web -> 2. (Sistem) Tampil Login -> 3. (Aktor) Isi Kredensial -> 4. (Sistem) Validasi -> 5. Dashboard/Error.
