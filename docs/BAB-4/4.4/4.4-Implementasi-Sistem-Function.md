# 1. Rancangan Tampilan Masuk Akun

Halaman Masuk Akun berfungsi sebagai antarmuka awal untuk proses otentikasi pengguna sebelum mengakses sistem. Pada tahapan ini, sistem melakukan verifikasi identitas melalui input surel (*email*) dan kata sandi (*password*). Mekanisme keamanan ini memastikan bahwa akses hanya diberikan kepada pengguna yang terdaftar dan berstatus aktif. Selain itu, proses *login* ini juga menentukan hak akses fitur yang akan ditampilkan berdasarkan peran pengguna, baik sebagai **Marketing** yang berfokus pada operasional penjualan, maupun **Direktur** yang memiliki otoritas penuh terhadap manajemen data dan analisis strategis.

Gambar 4.1 Rancangan Tampilan Masuk Akun

```php
    public function store(): RedirectResponse
    {
        // Validasi input email dan password harus terisi
        $this->validate(request(), [
            'email'    => 'required|email',
            'password' => 'required',
        ]);

        // Mencoba login menggunakan guard 'user'
        if (! auth()->guard('user')->attempt(request(['email', 'password']), request('remember'))) {
            // Jika gagal, kembalikan error ke sesi flash dan redirect kembali
            session()->flash('error', trans('admin::app.users.login-error'));

            return redirect()->back();
        }

        // Cek apakah status pengguna aktif (status == 1)
        if (auth()->guard('user')->user()->status == 0) {
            session()->flash('warning', trans('admin::app.users.activate-warning'));

            // Logout jika tidak aktif
            auth()->guard('user')->logout();

            return redirect()->route('admin.session.create');
        }

        // Mengambil item menu yang tersedia untuk admin
        $menus = menu()->getItems('admin');

        $availableNextMenu = $menus?->first();

        // Pengecekan izin akses ke dashboard
        if (! bouncer()->hasPermission('dashboard')) {
            if (is_null($availableNextMenu)) {
                session()->flash('error', trans('admin::app.users.not-permission'));

                auth()->guard('user')->logout();

                return redirect()->route('admin.session.create');
            }

            return redirect()->to($availableNextMenu->getUrl());
        }

        // Cek apakah pengguna memiliki akses ke URL yang dituju sebelumnya
        $hasAccessToIntendedUrl = $this->canAccessIntendedUrl($menus, redirect()->getIntendedUrl());

        if ($hasAccessToIntendedUrl) {
            return redirect()->intended(route('admin.dashboard.index'));
        }

        return redirect()->to($availableNextMenu->getUrl());
    }
```

# 2. Rancangan Tampilan Form Prospek

Formulir Prospek (*Lead Form*) dirancang sebagai instrumen utama dalam inisiasi siklus penjualan. Melalui antarmuka ini, pengguna dengan peran **Marketing** dapat merekam data calon pelanggan potensial beserta detail peluang bisnis yang teridentifikasi. Sistem secara otomatis memvalidasi kelengkapan data input dan menempatkan prospek baru ke dalam tahapan awal (*stage*) pada *pipeline* penjualan standar, sehingga memudahkan pemantauan dan tindak lanjut (follow-up) yang sistematis.

Gambar 4.2 Rancangan Tampilan Form Prospek

```php
    public function store(LeadForm $request): RedirectResponse|JsonResponse
    {
        Event::dispatch('lead.create.before');

        $data = request()->all();

        $data['status'] = 1;

        if (! empty($data['lead_pipeline_stage_id'])) {
            $stage = $this->stageRepository->findOrFail($data['lead_pipeline_stage_id']);

            $data['lead_pipeline_id'] = $stage->lead_pipeline_id;
        } else {
            if (empty($data['lead_pipeline_id'])) {
                $pipeline = $this->pipelineRepository->getDefaultPipeline();

                $data['lead_pipeline_id'] = $pipeline->id;
            } else {
                $pipeline = $this->pipelineRepository->findOrFail($data['lead_pipeline_id']);
            }

            $stage = $pipeline->stages()->first();

            $data['lead_pipeline_stage_id'] = $stage->id;
        }

        if (in_array($stage->code, ['won', 'lost'])) {
            $data['closed_at'] = Carbon::now();
        }

        $lead = $this->leadRepository->create($data);

        if (request()->ajax()) {
            return response()->json([
                'message' => trans('admin::app.leads.create-success'),
                'data'    => new LeadResource($lead),
            ]);
        }

        Event::dispatch('lead.create.after', $lead);

        session()->flash('success', trans('admin::app.leads.create-success'));

        if (! empty($data['lead_pipeline_id'])) {
            $params['pipeline_id'] = $data['lead_pipeline_id'];
        }

        return redirect()->route('admin.leads.index', $params ?? []);
    }
```

Gambar 4.3 Rancangan Tampilan Form Penawaran

```php
    public function store(AttributeForm $request): RedirectResponse
    {
        Event::dispatch('quote.create.before');

        $quote = $this->quoteRepository->create($request->all());

        $leadId = request('lead_id');

        if ($leadId) {
            $lead = $this->leadRepository->find($leadId);

            $lead->quotes()->attach($quote->id);
        }

        Event::dispatch('quote.create.after', $quote);

        session()->flash('success', trans('admin::app.quotes.index.create-success'));

        return request()->query('from') === 'lead' && $leadId
            ? redirect()->route('admin.leads.view', ['id' => $leadId, 'from' => 'quotes'])
            : redirect()->route('admin.quotes.index');
    }
```

# 6. Rancangan Tampilan Kelola Tanda Tangan

Fitur Kelola Tanda Tangan dirancang khusus untuk mendukung otentikasi dokumen digital. Dalam konteks ini, **Direktur** memiliki hak akses eksklusif untuk mengunggah dan mengelola gambar tanda tangan digital. Tanda tangan yang aktif akan dibubuhkan secara otomatis pada dokumen resmi keluaran sistem, seperti Penawaran Harga (*Quote*), guna menjamin keabsahan dan legalitas dokumen yang dikirimkan kepada klien.

Gambar 4.6 Rancangan Tampilan Kelola Tanda Tangan

```php
    public function store()
    {
        if (! bouncer()->hasPermission('settings.signatures')) {
            abort(403, 'This action is unauthorized.');
        }

        $this->validate(request(), [
            'name'       => 'required|string|max:255',
            'owner_name' => 'required|string|max:255',
            'image.*'    => 'required|mimes:bmp,jpeg,jpg,png,webp,svg', // Allow array input
        ]);

        $data = request()->all();

        if (request()->hasFile('image')) {
            // media.images sends an array of files, we take the first one
            $file = current(request()->file('image'));
            $path = $file->store('signatures');

            Signature::create([
                'name'       => $data['name'],
                'owner_name' => $data['owner_name'],
                'image_path' => $path,
            ]);

            session()->flash('success', 'Signature created successfully.');
        } else {
            session()->flash('error', 'Please upload an image.');
        }

        return redirect()->route('admin.settings.signatures.index');
    }
```

# 9. Rancangan Tampilan Pipeline Prospek

Tampilan Pipeline Prospek mengadopsi visualisasi papan Kanban untuk memetakan distribusi prospek berdasarkan tahapan penjualan (*sales stages*). Fitur interaktif ini memungkinkan tim **Marketing** untuk memantau dan memperbarui status progres setiap peluang bisnis, mulai dari tahap inisiasi hingga penutupan (*closing*). Visualisasi ini memberikan gambaran komprehensif mengenai kesehatan alur penjualan (*sales funnel*) perusahaan.

Gambar 4.9 Rancangan Tampilan Pipeline Prospek

```php
    public function get(): JsonResponse
    {
        if (request()->query('pipeline_id')) {
            $pipeline = $this->pipelineRepository->find(request()->query('pipeline_id'));
        } else {
            $pipeline = $this->pipelineRepository->getDefaultPipeline();
        }

        if ($stageId = request()->query('pipeline_stage_id')) {
            $stages = $pipeline->stages->where('id', request()->query('pipeline_stage_id'));
        } else {
            $stages = $pipeline->stages;
        }

        foreach ($stages as $stage) {
            /**
             * We have to create a new instance of the lead repository every time, which is
             * why we're not using the injected one.
             */
            $query = app(LeadRepository::class)
                ->pushCriteria(app(RequestCriteria::class))
                ->where([
                    'lead_pipeline_id'       => $pipeline->id,
                    'lead_pipeline_stage_id' => $stage->id,
                ]);

            if ($userIds = bouncer()->getAuthorizedUserIds()) {
                $query->whereIn('leads.user_id', $userIds);
            }

            $stage->lead_value = (clone $query)->sum('lead_value');

            $data[$stage->sort_order] = (new StageResource($stage))->jsonSerialize();

            $data[$stage->sort_order]['leads'] = [
                'data' => LeadResource::collection($paginator = $query->with([
                    'tags',
                    'type',
                    'source',
                    'user',
                    'person',
                    'person.organization',
                    'pipeline',
                    'pipeline.stages',
                    'stage',
                    'attribute_values',
                ])->paginate(10)),

                'meta' => [
                    'current_page' => $paginator->currentPage(),
                    'from'         => $paginator->firstItem(),
                    'last_page'    => $paginator->lastPage(),
                    'per_page'     => $paginator->perPage(),
                    'to'           => $paginator->lastItem(),
                    'total'        => $paginator->total(),
                ],
            ];
        }

        return response()->json($data);
    }
```

# 13. Rancangan Tampilan Analisis Market Basket

Halaman Analisis Market Basket merupakan fitur analitik lanjutan yang mengimplementasikan algoritma Apriori untuk menemukan pola asosiasi antar produk dalam riwayat transaksi. Fitur ini ditujukan khusus bagi **Direktur** untuk menjalankan simulasi analisis dengan parameter yang dapat disesuaikan (seperti nilai *support* dan *confidence*). Hasil analisis berupa aturan asosiasi (*association rules*) ditampilkan dalam bentuk tabel interaktif yang memberikan wawasan strategis mengenai perilaku pembelian pelanggan.

Gambar 4.13 Rancangan Tampilan Analisis Market Basket

```php
    public function index(): View|JsonResponse|BinaryFileResponse
    {
        $runs = AprioriRun::ordered()->get();

        $requestedRunId = request()->input('run_id');

        if (! $requestedRunId && $runs->isNotEmpty()) {
            $active = $runs->firstWhere('is_active', true);
            $requestedRunId = $active?->id ?? $runs->first()->id;
        }

        if ($requestedRunId) {
            request()->merge(['run_id' => $requestedRunId]);
        }

        if (request()->ajax() || request()->boolean('export') || request()->has('format')) {
            return datagrid(AprioriRulesDataGrid::class)->process();
        }

        $currentRun = $runs->firstWhere('id', $requestedRunId);

        return view('analyticalcrm::admin.analytics.market-basket.index', [
            'runs'          => $runs,
            'currentRun'    => $currentRun,
            'currentRunId'  => $requestedRunId,
        ]);
    }
```

Gambar 4.16 Rancangan Tampilan Laporan Analisis Market Basket

```php
    public function exportPdf(int $runId)
    {
        $run = AprioriRun::findOrFail($runId);
        $limit = 100;
        $totalRules = $run->rules()->count();
        $rules = $run->rules()->orderBy('lift', 'desc')->limit($limit)->get();

        $html = view('analyticalcrm::admin.analytics.market-basket.pdf', [
            'run'        => $run,
            'rules'      => $rules,
            'totalRules' => $totalRules,
            'limit'      => $limit,
        ])->render();

        return $this->downloadPDF($html, 'MarketBasketAnalysis_' . $run->id . '_' . date('d-m-Y'));
    }
```
